# Contract implementation

## Numerical conventions

- Token deposits and withdrawals use raw six-decimal USDC; internal quote balances use WAD. `FixedPointMath.usdcToWad` scales by `10^12`.
- `AmmState.k` is the unscaled product of WAD base and quote reserves. Its unit is WAD squared. Seeds reject products that exceed `uint256`.
- Each curve endpoint uses `ceil(k / baseReserve)`. Longs pay the difference between endpoint quote reserves; shorts receive that difference. PnL and entry cost use exact quote amounts, never a rounded average price. Zero-size, reserve-exhausting and malformed-reserve trades revert. Zero-quote opens revert; closes and hypothetical valuations allow a zero quote amount so dust can exit.
- Partial closes allocate entry cost by floor division. The final close removes all remaining entry cost, so the allocated costs sum exactly to the original cost.
- Worst long proceeds round down; worst short buyback costs round up. Initial margin takes the maximum of the leverage minimum, full impact minimum and protected funding-collateral floor (worst loss, maintenance and exit fee). Opening fees are separate.
- Side-cap basis points are derived with an exact integer inequality and binary search. The result is 128/557/1010/1715 bps at 20x/5x/3x/2x. Depth uses the applied cap and rounds up. Factory creation delegates the final depth and quote-cap checks to atomic market initialization after integer reserve seeding.
- Funding indexes use quote per base in WAD. Weighted obligations and remainders retain WAD-squared precision. The symmetric stored product domain is bounded by `int256.max`; overflows revert.
- Funding settlement uses a signed ceiling: payer debits round up and receiver credits round down in absolute amount. `roundingHi` tracks the difference exactly.
- `fundingPool` is signed. The exact surplus identity includes pending obligations, accrual remainder, settlement rounding, and prior sweeps. Sweeping may make the pool negative when accrued surplus has not yet been collected from payers.
- Taker fees round up; creator, insurance, and referral shares round down; protocol receives split dust and the unused referral share. Phase 1 has no skew premium. The skew-reducing fee discount is implemented.

## Public artifacts

`scripts/export_abis.py` reads compiler artifacts and writes fifteen deterministic JSON ABIs plus TypeScript `as const` exports. Run `make abi` after changing interfaces. The `--check` mode compares exports with the current build without modifying files.

`Market` implements `IMarketCore`. The extended `IMarket` interface describes future exact risk views and resolver methods; there are no placeholder implementations. SDK `marketAbi` and `marginVaultAbi` come from the concrete contracts. Deployment addresses and transaction-sending SDK methods remain future work.

## Vault integration

- The vault owns the authoritative per-market ledger. `settlePnl` balances locked collateral against signed clearing; `settleFunding` balances it against the signed funding pool. `chargeFee`, insurance funding/coverage, funding sweeps and claims have explicit counter-entries. No global accounting counter is written during trading.
- `locked[user][market]` is signed. The public `Position.margin` is its positive part, and `positionDebt(user)` is its negative part. Pending funding remains separate until settled; production accrual clamps before consuming protected collateral. Signed debt remains supported for recovery from legacy or other loss states. A voluntary full close covers debt from this market's insurance followed by the capped global backstop, emitting `BadDebt` separately for each source; an uncovered remainder reverts atomically. Forced liquidation additionally supports paired ADL and terminal settlement.
- Balanced accounting does not authenticate arbitrary market code. Registration is restricted to the governor's approved registrars; those registrars must deploy only the reviewed implementation. Registration is permanent to preserve exit access.
- Deposits/withdrawals use raw six-decimal USDC. Fee claims transfer only whole raw-token units and leave dust in the originating owed account. Direct token donations are outside the protocol transition model: they create unallocated excess cash and count toward the deposit cap; no sweep of that excess is implemented.
- A clone's registrar must register, fund, and initialize it atomically. The implementation itself cannot initialize; the clone permits only its recorded registrar, once. The vault must be deployed with its initializer encoded in the ERC-1967 proxy constructor.
- Vault upgrades require governor scheduling, the same implementation and initializer-data hash, and a 48-hour delay. Guardian or governor can cancel. Market pause does not affect vault withdrawals. Risk-parameter timelocks and cap changes are still future governance work.

## Operators and quotes

- Operator expiry is a **block number**, exclusive: `block.number >= expiry` rejects. `setOperator` replaces the policy and resets consumption. Both opens and closes consume actual curve quote notional; closing additionally requires `canClose`. Operators cannot add/remove margin or withdraw.
- Market leaves use `keccak256(bytes.concat(keccak256(abi.encode(market))))`, with sorted Merkle pairs. The five-argument `openFor`/`closeFor` overloads carry the proof. The four-argument overloads use an empty proof, suitable for an unrestricted root or a single-leaf tree.
- `quoteOpen(size)` quotes for `msg.sender`; operators should use `quoteOpenFor(user,size)`. Returned margin is the **additional** free collateral required after simulated funding settlement. Fees are additional. Opens increase an existing position on the same side; closing to zero is required before changing sides.
- `quoteClose` returns the closed portion's curve PnL and fee, but funding owed for the entire position, matching execution. Partial closes retain collateral; `removeMargin` checks both worst-case initial margin and reference equity. A full close removes all remaining entry cost and releases all positive collateral.
- A buy's limit is a maximum price and a sell's limit is a minimum. Use transaction simulation to check authorization, balance, current oracle data and status; numerical quote views do not perform external oracle updates or consume a policy.

## Bounded position book

- A market admits its configured `maxPositionsPerMarket` nonempty positions (2–128, launch default 128). A user's first open adds one entry; increasing or partially closing retains it. Full voluntary close or liquidation removes it and immediately frees a slot. Failed operations roll back book changes with the rest of the trade.
- `positionCount()` and `positionAccounts(offset, limit)` expose the complete book in bounded pages. Limits above 256 revert. Slots remain fixed for a position’s lifetime. Full close leaves a zero-address hole, reused from a free list on a later open. Pages include holes; `positionCount()` counts live positions. Pin a block across pages and skip zero addresses. Surviving positions never move.
- The 128-position cap fits within the vault's 256-address custody limit. Local regressions require each full-book settlement and each bounded ADL call to stay below 20 million gross gas; 256 positions exceeded that budget in the earlier settlement implementation. Target-chain fork validation remains required. No minimum position size is introduced; capacity is first come, and increases/exits remain possible at the position limit.
- Storage is appended to the undeployed market namespace. Existing deployed clones without a populated registry would need a separate migration; this repository has no deployed market to migrate.

## Oracle and TWAP integration

- Funding accrues against the cached observation before a fresh price is installed. For external markets it stops at the first degraded block, so a later fresh update does not retroactively charge the outage. Oracle-less funding uses mark TWAP and skew.
- Opens read the primary source and can fall back to a configured secondary. `poke` attempts reads without a paid update; fresh observations can restore Active status. `remark(bytes)` supports paid updates. A guardian pause survives all price refreshes; only the governor can resume opens.
- **Closes do not call an adapter.** Their update bytes are ignored for ABI compatibility and nonzero native value is rejected. They can transition the market to Degraded from cached age. A successful primary/secondary observation on a subsequent `poke` or `remark` restores activity.
- TWAP stores cumulative mark-by-block integrals in a 601-slot ring. Same-block trades replace the final mark for the next interval and do not receive time weight immediately. Before one block has elapsed, the initial mark is the reference. A binary search finds the observation bracketing the 300- or 600-block window; sparse intervals are interpolated.
- `MarketTrading`, `MarketLiquidation`, `MarketMargin`, `MarketAdl`, `MarketSettlement`, `MarketLens`, `MarketAccounting`, `MarketFundingCapacity`, `MarketMaintenance`, `FundingMath` and `MarkTwap` use linked library calls. Their addresses are fixed in the implementation bytecode and must be verified alongside the market implementation at deployment. Solidity 0.8.30 uses the IR compiler to keep the runtime within the EIP-170 limit. Run `make build` to enforce the size gate as the implementation grows.

## Backstop and module foundations

- `InsuranceBackstop` holds policy and claim budgets; all USDC and the global WAD balance remain in the vault. Anyone can irrevocably contribute from their free balance. The governor binds the controller once; replacing it requires a delayed vault upgrade.
- Each market snapshots 20% (external index) or 10% (oracle-less) of the available global balance on its first claim in a 288,000-block window. Subsequent claims subtract from that fixed budget. Deposits cannot reset it; another market's claims can reduce available cash. A new window starts at the next claim after expiry. These are fixed windows, not rolling windows or wall-clock days.
- Permissionless `topUp` moves insurance above `ceil(2 × current oiCap / multiplier)` into the backstop. Launch OI caps still apply and no backstop allocation is counted toward opening capacity.
- Vault `coverBadDebt` balances insurance and capped backstop credits against negative locked collateral and returns any remainder. Only trusted market implementations may call it; they must handle that remainder atomically. Voluntary full close uses this path; covered liquidation uses the selected-share `coverLiquidationLoss` path.
- Penalty accounting debits at most positive locked collateral, credits 40% to the caller's free balance (rounded down), and the rest to insurance. An insolvent account cannot generate insurance-funded keeper rewards. The earlier locked-only transfer primitive is separate from paired ADL. Paired execution settles both positions at a shared value and consumes only its protected per-position reservation; it cannot spend another pending position’s reservation.
- Market state now lives at the fixed `pripo.market.storage.v1` namespace shared by immutable linked modules. This changes the layout of undeployed market implementations and is not a migration for existing clones. The vault additions are append-only. All external market mutations retain the market's reentrancy guard; modules cannot replace their linked targets at runtime.

## Liquidation integration

- Anyone may call `liquidate(user, update)`, including during a guardian pause. It accrues cached funding, refreshes the external index when not degraded, settles the position's funding, then checks maintenance health, negative post-funding collateral or the funding-capacity binding predicate. Negative collateral and a binding cap are liquidatable even when unrealized PnL puts health above maintenance. Empty positions and positions satisfying none of these predicates revert. Non-degraded external markets require a fresh primary/secondary observation; supplied update fees are forwarded to the primary.
- Degraded liquidation uses the 600-block TWAP without calling an adapter and rejects native value. A separate successful `remark` or `poke` can restore oracle operation. Oracle-less liquidation also rejects native value. Terminal settlement always freezes the 300-block TWAP, including in Degraded mode.
- The selected close is 50% above 50,000 quote notional for external markets or 10,000 for oracle-less markets, otherwise 100%. Threshold notional uses the fresh index, or TWAP in degraded/oracle-less mode. Fractional quote wei above the boundary count as above it. Degraded mode closes at most half per call, except the final one base wei. Whole-market forced settlement overrides this partial-close limit.
- A normal partial's projected remainder must satisfy maintenance after the penalty; otherwise preflight selects a full close before trading. Degraded mode retains its half-size limit even if another call is needed.
- The 150-bps penalty is calculated once on the selected curve quote, rounded up, and capped to positive collateral after funding and before PnL. It is charged before choosing the coverage path: 40% to the caller (rounded down), the rest to insurance. The same penalty applies if execution pairs off-curve or settles the market. No ordinary taker fee is added.
- Preflight compares the selected share of signed post-penalty collateral plus selected curve PnL to local insurance and currently available capped backstop coverage. Negative selected collateral rounds up in magnitude. Covered partial liquidation consumes coverage only for that selected debt and retains the unselected funding debt in locked. Covered execution uses actual curve reserves and the ordinary close transition; partial collateral stays locked, and a full close releases the positive balance. Insufficient coverage invokes paired ADL before committing any fill or winner payout.
- `Liquidated.badDebt` is coverage consumed for a curve/paired close, or the final protocol deficit for terminal settlement. `BadDebt.coveredBy` distinguishes local insurance (0), capped backstop (1) and consumption of reserved ADL loss coverage (2); restoration emits the vault’s `AdlCoverageRestored`. Terminal sources have separate events. An initial empty-list ADL reports zero matched size and average; the once-only penalty remains in that `Liquidated` event.

## Pending paired ADL

- The two-argument `liquidate` ranks the complete book by descending score and address ties, then matches up to 64 candidates. The explicit overload and `continueAdl(user, candidates)` accept unique eligible accounts in nonincreasing score order, without requiring global top-k. A valid insufficient list leaves a pending remainder when the full book is sufficient; invalid lists revert atomically.
- Candidates must be opposite-side, non-pending, have nonnegative post-funding collateral, and earn strictly positive exact schedule-ratio and full-position TWAP realizable profit. Eligibility compares 512-bit cross-products. Score is `floor(realizablePnl × entryCost × WAD / collateral²)`, saturating at `uint256.max`; zero collateral receives that maximum. Entry and quote bounds use the validated launch caps.
- Initiation charges the penalty once and snapshots selected size `S0`, entry `E0`, signed collateral `M0`, coverage `C` and signed budget. Actual insurance and capped backstop move into a position reservation, committing the backstop window once. The lifetime allowance target is the configured book cap in quote wei. It comes from `C` first and protocol reserve second; paired coverage is `C − allowanceFromC`. Unused reserve-funded allowance returns to reserve; other unused reservation funds return to local insurance.
- With `B = M0 + pairedCoverage`, scheduled value `V0` is `E0 − B` for a long loser and `E0 + B` for a short. A negative short boundary has no eligible long; the fresh scan proves insufficiency and settles. For executable schedules, each chunk removes differences of `floor(E0 × matched / S0)` and `floor(V0 × matched / S0)`. The shrinking-position partial-close helper is bypassed. Per-candidate realizable bounds add relief for long losers and subtract it for shorts, so actual values sum to `V0 ± relief` and booked loss to `B − relief`.
- Matching is greedy. Short-winner entry proceeds round up; long-winner entry costs and nonnegative collateral shares round down. Booked profit is nonnegative. A zero-profit chunk receives exactly one quote wei from its reserved allowance after loss coverage is committed, or emits `AdlZeroProfit` when allowance is exhausted. Opens are paused, so each candidate is consumed at most once and lifetime chunks are bounded by the book cap. No redistribution or allocation search remains.
- Pending owners cannot close, remove margin or be matched/liquidated again. Added margin replaces only currently unspent loss coverage one-for-one, returning it to insurance; snapshots and deadline stay fixed. Prefix coverage is provisional: `max(floor(pairedCoverage × matched / S0) − relief − replacedC, 0)`. Later relief/replacement can restore previously credited coverage from locked to reservation. The loser receives no interim free balance; completion releases only the selected residual permitted by the existing vault guard, preserving unselected debt.
- Funding is checkpointed on initiation, remains zero while any pending exists, and advances its time checkpoint without catch-up accrual. Pending count, Guardian pause and oracle degradation are independent. Resolving one of several pendings cannot restore funding or opens; the last completion preserves the other pause reasons. The global reserve/deficit admission gate still applies.
- `completeAdl(user, maxIterations)` becomes callable after the fixed `since + adlPendingWindow` (launch 1,000 blocks). Each call first scans the complete book, then visits 1–64 stable slots from a persisted cursor. Holes count as progress; end-of-book wraps to zero. The deadline enables enumeration only. With finite external book mutations, repeated calls complete or prove insufficiency; they cannot guarantee progress without submitted transactions or under unlimited adversarial eligibility changes.
- Inspect `pendingAdl(user)`, `pendingAdlCount()`, `adlEligibleSize(user)` and the vault reservation views. `AdlPending.reservedC` in the event is the current remaining reservation; the struct’s `reservedC` is original `C`. `AutoDeleveraged` identifies both parties and the actual shared value and winner entry; it no longer reports a rounded execution price. One quote wei is `10^-18` USDC, below the `10^12` quote wei needed for one raw token unit.

## Whole-book forced settlement

- Execution is reachable only from initiation or continuation after a fresh complete-book scan proves eligible opposite size below the pending remainder. All this market’s pending reservations are released to their named sources before terminal valuation; another market’s reservations remain isolated. `settlementQuote()` is a hypothetical whole-book view, before a keeper penalty or fresh oracle update; calling it does not authorize settlement. It returns frozen price, position count, collected losing collateral, eligible profits, isolated debt, post-valuation signed clearing, funding surplus, haircut and remaining capital requirement.
- Preflight simulates all pending funding, then values every long with a floor and every short with a ceiling at the common 300-block TWAP. Haircuttable profit is `min(positive ending equity, positive(trading PnL − unsettled funding))`. This includes pending funding receipts. Already-realized collateral is principal for this allocation; free balances and prior withdrawals are outside it.
- Let `D` be total negative ending collateral, `C` the post-valuation signed clearing, and `I` local insurance including the final funding surplus. The pre-haircut gap is `max(D − C − I, 0)`. The haircut is the lesser of this gap and total eligible profits. Prefix-floor allocation over the captured book order sums to the exact haircut; each account differs from ideal pro-rata by less than one quote wei. Caller candidate order does not choose the haircut order.
- Execution enters `Settling`, settles all funding/PnL/haircuts before any release, removes every position and weight, sweeps the final funding surplus, and resets virtual reserves at the frozen price. The vault nets signed clearing and remaining isolated debts through explicit counter-entries: surplus clearing becomes local insurance; negative clearing increases the terminal funding requirement. Virtual reserve reset alone never erases cash obligations.
- The market enters `Settled`, calls the vault capital waterfall once, then releases positive collateral to free balances. Funding stops permanently and position counts, both side totals, entry cost, clearing and funding pool are zero. `poke`, `remark`, opens, resume and reseed cannot reopen it, including after recapitalization. `settlementInfo()` retains price, total haircut and eligible profits.
- `AdlInsufficient` identifies the pending user and the fresh eligible/required sizes. `ForcedSettlement` carries terminal TWAP, pre-haircut shortfall and deepest capital step: 0 local balances, 1 haircut, 2 local fees, 3 backstop, 4 reserve, 5 deficit. `SettlementHaircut` carries exact eligible profits and haircut; `MarketSettled.haircutBps` is the ratio rounded up for display. `TerminalCoverage` sources 1/2 are emitted by the market for collateral/haircut; sources 0 and 3–7 are emitted by the vault. `TerminalClearingNetted` records the signed clearing and isolated debt before netting. Indexers must listen to both addresses.

## Reserve and terminal-capital custody

- `protocolReserve`, `deficit[market]` and their control aggregates are appended to the existing UUPS vault storage. The signed cash identity adds reserve and subtracts each deficit once. Aggregate reserve budgets and `totalDeficit` are controls, not additional cash accounts.
- Clone initialization admits its fixed launch parameters only with zero total deficit and at least 10,000-USDC actual reserve cash. Funding contributes no reserve budget: its indexes are constrained by each payer's collateral. Deprecated aggregate/budget slots remain for storage layout compatibility; new admissions leave them zero. Zero-rate markets are supported. Parameter changes are not implemented.
- Every owner/operator open passes the vault gate before operator-policy consumption. Any positive deficit or underfilled reserve blocks opens; closes, margin operations and withdrawals retain their existing rules. Governor resume also checks the gate. Numerical quote views remain calculations; use `requireOpenAllowed(market)` and transaction simulation to check current execution eligibility.
- `finalizeSettlement(debtors)` is a trusted-market custody primitive, called once after the engine has realized the whole book and applied losses/profit haircuts. It verifies `Settled` and zero aggregate long/short sizes, sums remaining negative collateral, nets signed clearing, and uses remaining local insurance, local creator fees, local protocol fees, uncapped actual global backstop, then reserve. Each negative collateral account becomes zero; only the final remainder is booked as protocol deficit. No free/referral balance is debited. Duplicate debtors cannot count twice. Finalization makes no additional live-window claim; the initial ADL reservation has already committed its live claim once.
- The terminal primitive accepts at most 256 debtor addresses; the market supplies its complete book of at most 128. Valuation, haircuts, ledger counter-entries, finalization and releases occur in one atomic call. Registration still trusts the reviewed market implementation to supply all accounts and keep `Settled` terminal. Local gross-gas tests bound full execution; Monad fork validation is outstanding.
- `allocateProtocolFees(market, maxEntries)` moves protocol fees to the oldest terminal deficits first, then fills reserve to its current floor. Remaining fees stay in the originating ledger. A minimum heap orders deficits by creation timestamp and numeric market address for ties. Each call processes at most 32 entries. Targeted recapitalization may leave cleared queue entries; bounded allocation prunes these even when the selected fee ledger is empty. `deficitQueueHead` can therefore return a cleared entry awaiting pruning.
- `claimProtocolFees` transfers only whole USDC units to treasury, with an enforced zero-deficit and funded-floor gate. Allocation and claims are separate, so a partial repayment/refill succeeds even while treasury claims remain blocked. These are the custody primitives used by the batch `FeeSweeper`; there is no ungated direct protocol-fee claim path.
- `fundProtocolReserve(rawUsdc)` irrevocably transfers actual tokens, repays oldest deficits, then credits reserve. `recapitalize(market, rawUsdc)` repays a selected terminal deficit; excess follows the other deficits' priority before reserve. Both reject transfer taxes, hold the vault guard, and bypass the user deposit cap so emergency funding cannot be blocked by that cap. They cannot process more than 32 queued entries per global allocation; an excessive contribution reverts atomically. Split contributions or first repay/prune the backlog through fee allocation or WAD-denominated free-balance donations. `contributeToDeficit(market, wad)` debits the contributor's own free balance and the selected deficit without token inflow or a duplicate reserve/user credit.
- Capital-account mutations share the vault reentrancy guard with token transfers, including treasury claims. Reserve events use reasons 0 (contribution), 1 (fee refill), 2 (terminal draw), 3 (ADL allowance), 4 (unused allowance return); deficit events use 0 (booking), 1 (fees), 2 (recapitalization/free contribution). Terminal source codes are 0 (remaining insurance), 3 (creator fees), 4 (protocol fees), 5 (backstop), 6 (reserve), 7 (deficit); the market engine emits losing-collateral/profit-haircut sources 1 and 2.

## Accepted target policy and next milestone

The updated protocol spec resolves the ADL and terminal-shortfall choices:

- ADL pairs equal opposite sizes off the curve on the fixed value schedule, with no reserve movement; `p_adl` is an exact eligibility ratio only. Paired PnL and entry-cost removal preserve clearing. Submitted candidates are checked for eligibility and score ordering; the keeper uses the indexer for ranking.
- Insufficient eligible size triggers whole-market settlement at the 300-block mark TWAP. After applying remaining market insurance, funding comes from losing collateral, open-profit haircuts, this market's unclaimed creator/protocol fees, the global backstop without its live daily cap, then a protocol reserve. Only the remaining gap becomes protocol deficit on a `Settled` market.
- The protocol reserve floor is `10_000e18`, retained for ADL rounding and terminal coverage. Funding uses no reserve allocation. The floor requires initial cash funding. Protocol allocations repay terminal deficits first, refill reserve second, and distribute to treasury last. Every successful treasury sweep must leave the reserve floor intact and aggregate deficit zero.
- In Phase 1 any terminal deficit globally pauses opens. The Guardian must arrange and verify recapitalization within 24 hours. Deficit repayment does not reopen a settled market. `Impaired` and the advanced-profit claims cap remain Phase 2.

**Implementation status:** reserve admission, terminal custody sources, deficit booking/repayment, global opens controls, treasury gates, reserved pending ADL, permissionless continuations and whole-book forced settlement are implemented. Voluntary full closes still revert on uncovered debt; liquidation is the recovery path. Factory creation, Pyth/null adapters and batch fee sweeping are also implemented. Resolver-driven settlement and Phase 2 claims remain future work. Runtime ABIs are generated from concrete contracts; nothing is deployed.

**Remaining design/verification gates:**

1. A recorded protocol deficit is not a cash asset. After protocol capital is exhausted, deficit booking can leave nominal user balances larger than available cash. Payer capacity now bounds funding accrual and preserves trading collateral. Future resolver valuation, parameter changes and other collateral-spending paths must preserve that protection. Guardian top-up promises do not fund a pre-existing deficit.
2. The agreed ADL dust and continuation mechanism is implemented and tested: greedy fixed schedules, funded allowance and fresh full-book insufficiency. Preserve these properties when adding future resolver or risk-parameter transitions.
3. Full-book terminal and ranked ADL fork scenarios now pass with real signed Pyth updates and native USDC. Complete Monad-native estimation and testnet charged-fee measurements, including final oracle payloads and linked-library deployment settings. The current local 20-million-gas budget is a regression threshold, not a network guarantee; see [Monad integration](monad-integration.md).
4. The Phase 2 advanced-profit cap must reserve capacity across recipients and include positive funding receipts, so receivers cannot bypass it by settling and withdrawing before a close.

Next implementation work includes these deployment gates, exact remaining risk views (`liquidationPrice`, `maxOpenable`), live adapter/factory fork validation, resolver governance integration and parameter changes. The runtime has not been deployed.

Five invariant suites cover numerical funding, actual-token trading, eight-market synthetic capital allocation, liquidation/ADL/terminal recovery from an explicit historical-debt fixture, and payer-backed funding across two production markets. The recovery handler includes block advances, margin changes, partial closes, capital contributions, fee allocation and withdrawals bounded by actual cash; its purpose is signed accounting and terminal mechanics. The separate backing handler uses no liquidation, synthetic debt or recapitalization and never reduces a withdrawal to available cash. It checks funding capacities, both heaps, frozen bindings, payable balances and signed custody, then fully unwinds receivers before payers. The former integer-fragment boundary is covered by the integrated funded-rounding and pending-continuation tests.

### Payer-funded capacity and recovery

`MarketFundingCapacity` is integrated with the production market. For a position's fixed entry notional, the protected amount is `max(worstCloseLoss, 0) + ceil(entryCost * mmrBps / BPS) + ceil(worstCloseQuote * takerFeeBps / BPS)`. Initial margin also covers this floor. Available funding capacity is the positive excess of its own locked collateral above that amount. The key is `lastFundingIndex + floor(capacity * WAD / abs(size))`. The configured maintenance rate is used; temporary Degraded health requirements do not retroactively change funding keys, and Degraded suppresses new funding.

Each side uses `FundingCapacityHeap`: one signed key per live position, at most 128, ties by address, indexed updates/removals with no stale-entry accumulation. Every completed position/collateral mutation refreshes the key after fees, PnL, releases and coverage, including both ADL legs and terminal removal. The seed-based curve bound and entry notional make untouched keys stable under price moves.

`FundingMath.accrueCapped` advances the payer index only through the minimum headroom and derives receiver credits and surplus from that amount. It clamps before multiplying elapsed blocks and checkpoints the complete interval. Reaching the bound latches a binding address. Both indexes remain frozen across rate reversals, oracle refreshes, unrelated touches and sweeps. A completed binding-position touch clears the latch only if the position closes or its refreshed key exceeds the side index. There is no catch-up accrual and a sub-quantum top-up may leave the freeze in place. Pending ADL and oracle/Guardian status remain independent.

Every positive funding settlement asserts the debit is no greater than current capacity before the vault mutation. Negative/zero funding does not need capacity; existing debt can still be handled by recovery paths. `fundingCapacity`, `fundingLimit` and `fundingBinding` expose the current calculation and effective preview binding. Freeze/resume events identify the binding account.

The binding account is explicitly liquidatable even when its ordinary equity health exceeds maintenance. The standard penalty and sizing rules apply. This is a new predicate, not a consequence of the original health formula. A position opened exactly at the protected floor has no funding headroom; it can bind as soon as funding would charge it. Its owner can add margin or close, or a keeper can use the explicit capacity predicate.

A nonnegative-collateral voluntary partial close also preserves the remaining worst-close loss plus whole-close fee. Repeated per-chunk fee rounding cannot consume that residual backing. If it cannot be preserved, the partial reverts; a fully backed full close or added margin remains available. Existing negative collateral retains the established recovery semantics.

The two proposal regressions remain documented in validation history: maintenance alone left 44.0043 USDC against a permitted 81.0205-USDC curve loss, and a profitable binding payer was healthy under the old health predicate. The current proposal probe verifies that production now rejects the obsolete larger funding debit. Debt-recovery tests explicitly seed the retired uncapped model through `DebtShockMarket`; that entry point is absent from production. They remain mechanical ADL/terminal tests, while the separate multi-market backing invariant uses ordinary production transitions, no debt injection, no liquidations and no recapitalization.

The eight-period funding reserve model is retired. The current floor is 10,000 USDC; no additional non-funding sizing term has been selected. A recorded terminal deficit still does not create cash. None of these changes upgrades existing immutable market clones, supplies deployment funds or implements resolver/parameter changes.

Monad mainnet RPC access and a Pyth API key are configured locally. The upgraded provider, native USDC and ten equity IDs have been verified; BTC and TSLA signatures pass against the real provider. The current key does not grant the other four regular equity candidates or the five Index feeds. Their entitlements and off-hours observations remain necessary before primary/secondary selection. Testnet execution follows with a funded deployer and explicit governance/Guardian/Council addresses. Reports separate local execution gas, RPC estimates, submitted gas limits and actual charged fees; a local fork alone does not establish Monad fee charging or execution timing. Launch funds and a live deployment are still pending.

## Factory and feed escrow

- `MarketFactory` deploys deterministic clones with the exact, case-sensitive symbol hash as salt. Symbols contain 1–64 bytes; uniqueness is global to that factory. Existing symbols remain bound to their original markets after implementation changes, and `predictAddress` returns that deployed address. Predictions for unused symbols use the current implementation and can change after a scheduled activation.
- Creation pulls raw USDC from the creator’s approved wallet, registers the clone, deposits the bond through the vault, moves it into market insurance, and initializes the reviewed runtime in one guarded transaction. Rejection at any point restores tokens, registry, salt and admission budget. Bond deposits count toward the vault deposit cap. The factory retains no new free balance. Creators cannot override the 5x/2x launch risk sets, fees, funding caps, pending window or book cap.
- Use the factory’s canonical `nullAdapter` with feed zero for oracle-less markets. External creation requires an approved adapter and bonded supported feed; each adapter/feed pair admits one market. `createMarket(params, update)` forwards a pull-update fee before initialization; `createMarket(params)` reads the current cached feed. External initial price comes from the adapter and ignores the creator’s supplied price.
- Adapter approval and implementation replacement require a one-day schedule, then permissionless activation. Governor schedules; Guardian or governor can cancel pending implementation changes or disable an external adapter immediately. This affects future creation only. Existing clones and their configured sources stay fixed. The vault must separately authorize the factory as a registrar, and every admitted implementation/adapter remains a governance trust boundary.
- Permissionless `listFeed` escrows 500 USDC (500e6 raw units) for 30 timestamp days. `isSupported` establishes that the provider has a feed, not that its economic meaning matches a creator’s symbol. Governance reviews misconfiguration. Anyone may trigger a mature refund, which always pays the original lister and leaves the feed listed. A listing cannot be duplicated or refunded twice.
- Only the governor can slash a listing, recording a nonzero reason hash. Revocation immediately moves any unrefunded bond from `refundableBonds` to `slashedBonds` without an external transfer. Refunded bonds cannot be clawed back. Revoked feed pairs cannot be relisted by callers; existing markets still require their normal Guardian/resolver response.
- The slash destination is immutable constructor configuration: protocol reserve or global backstop. Deployment must select the intended policy. `allocateSlashedBonds(rawUsdc)` is permissionless and separate from revocation: reserve contributions repay deficits first and obey the vault’s bounded allocation limit; backstop contributions use deposit plus free-balance funding and therefore obey the vault deposit cap. A blocked allocation leaves the revoked state and slashed escrow available for a later batch.
- Under protocol transitions, factory token cash equals `refundableBonds + slashedBonds`; this is separate from vault cash. Direct donations create unallocated excess, with no rescue/sweep implemented. Current creation metadata preserves the original creator; the transferable current creator remains the vault/market role. Bond return on market wind-down depends on the future resolver integration.

## Oracle adapter boundary

- `PythAdapter` binds one Pyth Core contract, maximum age for supplied updates, and a milliseconds-per-block estimate at deployment. Launch fixtures use 3 seconds and 300 ms. `update` is `abi.encode(bytes[] signedPythUpdates)`; empty bytes read cached state. The adapter forwards exactly `getUpdateFee(payload)`, rejects under/overpayment, calls the provider’s update verification, and reads `getPriceNoOlderThan` after an update. Empty reads use `getPriceUnsafe`, retaining the returned publication age for the market to reject stale data. These signatures follow the [Pyth update API](https://api-reference.pyth.network/price-feeds/evm/updatePriceFeeds) and [price-read API](https://api-reference.pyth.network/price-feeds/evm/getPriceNoOlderThan).
- Positive signed prices normalize to WAD with floor rounding and the market’s `1e28` limit. Zero, negative, sub-wei, future-dated and unrepresentable observations reject. Confidence rounds upward in basis points, saturating at `uint16.max`; the market still rejects values above 100. Block age is `ceil((now − publishTime) × 1000 / blockTimeMillis)`. An age predating block zero rejects instead of becoming artificially fresh. This is a timestamp-derived estimate, not proof of the publication’s exact chain block; verify timing assumptions on the deployment chain.
- `isSupported` checks whether Pyth has a cached observation; it does not require freshness or replace trade-time validation. Price verification remains in the deployed Pyth provider. Local `MockPyth` data is an ABI test encoding, not a VAA/signature verifier. No production Pyth address is hardcoded or deployed by these changes.
- `NullAdapter` supports only feed zero, returns zero price/current block/zero confidence/non-external, and rejects update bytes and native value. Chainlink adapters and market-hours handling remain later work.

## Batch fee sweeping

- `FeeSweeper` accepts 1–32 distinct registered markets. `allocate(markets, maxEntries)` performs repayment/refill with 1–32 deficit-queue entries per market and no token transfer. `sweep(markets)` uses 32 entries per market, allocates the whole batch first, then claims remaining protocol fees only if aggregate deficit is zero and reserve is funded.
- If the treasury gate remains closed, successful partial allocation persists and payout is zero. Unprocessed fees stay in their source ledger for later calls; a caller can reduce batch size/queue budget for gas. No callback can redirect the vault’s stored treasury, and the vault rechecks its gate on each claim. Claims floor to raw six-decimal USDC and leave dust owed. The sweeper owns no escrow and adds no fee or bounty.
